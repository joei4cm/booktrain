## 2. Assessment B：确定性检测器

**对运行中的页面**（`detect --json http://127.0.0.1:8788`）：

| 严重度 | 规则 | 详情 |
|---|---|---|
| warning | `skipped-heading` | `<h1> "booktran" followed by <h3> "上传" (missing h2)` |
| advisory | `flat-type-hierarchy` | `Role sizes: h3 11px, body 13px, h1 14px (largest adjacent step 1.18:1; target 1.25:1)` |

**对源码**（`detect --json src/booktran/web/`）：同样一条 `skipped-heading`，无其他命中。

**读法**：detector 只报出 2 条，**不是因为界面干净，而是因为它足够平庸**。
它没有"仪表盘卡片墙""渐变文字""emoji 图标"这类反模式——因为这个界面本来就是
GitHub Primer 控件 + 13px 系统字体的直接拼装。**detector 能查的是形，查不了义**：
费用不可见、没有书页、状态维度缺失、按钮状态机错误，它一条都查不出来。

**假阳性**：0 条误报；两条命中都是真问题（h1→h3 跳级、字号级差不足）。

## 3. Assessment A：独立设计评审（子代理，未见 detector 输出）

### 3.1 设计专属性判定

**数据模型是 booktran 的，界面不是。**
陌生用户会一眼认出「GitHub 风格 admin/dashboard」——配色逐字取自 GitHub Primer，
但认不出 booktran：全页没有书名、封面、章节、"页"的概念，书名只以目录名出现
（`index.html:268` ← `app.py:546-554` 的 `booktran-<名>-2`）。

**仅三处专属**：段落表的"每语言一条轨道"（`index.html:410-421`）、
术语表 `dst_<lang>` 覆盖列与"回落默认"（`index.html:377-382`）、
翻译背景的 10 个书籍领域字段（`index.html:210-212, 353-361`）。

**关键反差**：`PRODUCT.md:64` 写明工作台"不是仪表盘，是**一张摊开的书页**"，
当前 UI 恰恰是它否弃的仪表盘——原文/译文是两个表格单元格里的 12.5px 无衬线编辑框，
不是可排版书页。**像素层面 category-interchangeable，schema 层面 authored。**

### 3.3 认知负荷

**8 项清单失败 7 项 → 高认知负荷（临界）。**

- 单一焦点 ✗（5 标签页 + 2 个常驻头部动作 + 侧栏上传互相争抢）
- 分组 ✗（"翻译背景" 10 字段 `:210-212`；"模型服务" 9 控件 `:129-150`）
- 视觉层级 ✗（头部按钮与标签页同级；概览四按钮同权重）
- 一次一事 ✗（"开始翻译"常驻任意页顶部；一份 glossary 三个保存按钮）
- 最少选择 ✗（见下）
- 工作记忆 ✗（侧栏语言字段 `:86` 与设置页 `:155` 并存且不同步；改完设置必须记得点"保存设置"，无 dirty 标记）
- 渐进披露 ✗（10 字段背景恒展开；术语分析不在术语页）

**可见选项 >4 的决策点**：①"模型服务"9 个控件同屏；②"翻译背景"10 个；
③上传目标语言 = 19 语言自由文本；④术语表每行 `2+N` 个输入且固定 `width:90px`（中文译名放不下）；
⑤概览动作行 4 按钮混排，"删除项目"与"术语分析""VLM 重读"并排（`:119-124`）。

### 3.4 情绪旅程

**Peak-end 失败**：全书最贵的一刻结束**零确认**——无完成 toast、无头栏变化、无通知；
轮询只更新概览页，用户停在"段落"页会以为还在跑（B5）。

**谷底**：
1. **花钱前空洞**——无估算、无已花、无预算；概览只有 token（`:293`），
   而 `Stats`（`model.py:157-175`）与 `summary()`（`app.py:113-154`）**根本没有金额字段**；
   CLI `status` 也只打 token（`cli.py:250-251`），而 README:29 宣称"查看进度/成本"。
2. **不知道在翻哪本书**——顶栏只显示 `provider/model · 源 auto`（`:279`），各项目完全相同。
3. **跑完按钮卡死**（B3）。
4. **静默吞编辑**（B1）。
5. **无退出的长跑 + 假成功反馈**（B4 + B2）。

**高风险时刻的安抚**：全应用只有一个 `confirm()`，用在删除项目（`:460`）；
真正花钱的三个动作（开始翻译 / 术语分析 / VLM 重读——后者是全书页图多模态调用）
与"导出未完成的书"全部**零确认、零预估、零预算**。

### 3.5 做得好的三点

1. **长任务反馈骨架是真的**：每语言进度条带 `translated/total（%）`（`:296-299`）、
   日志按轮次/块数/待翻数汇报（`:490`）、后端 `Progress` listener 真实落事件（`app.py:358-361`）。
2. **多语言轨道编辑模型是为本产品写的**：一行一段，每目标语言一编辑框 + 每语言状态；
   术语表用 `dst_<lang>` 覆盖列把"回落默认"摆上台面。
3. **翻译背景表单是唯一说人话的地方**：把 `glossary.json` 的技术字段映射成
   "书名/题材/时代/命名规则/目标读者"等 10 个书籍领域标签，并说明"随每次请求注入提示词"。

### 3.6 人群红旗

| 人群 | 会被卡在哪 |
|---|---|
| 首次使用的公众用户 | 落地只有"上传文件或选择左侧项目"（`:101`），无"先配 API key"引导；必须先知道 `chinese_simplified`；`fake` 与 `openai` 并列无从判断；按下"开始翻译"前不知花多少钱；术语空状态把人推向 `glossary.json`；书名只是目录名 |
| 做术语工作的译者 | 术语分析在"概览"；不能增删术语行；备注不可编辑；输入框 90px 放不下中文译名；"默认译名"与各语言覆盖列的关系只能从占位符猜；切页保存背景会静默丢弃未保存的术语编辑（B1）；`dst_<lang>` 覆盖规则界面完全无说明 |
| CI 里的 power user | 无快捷键；导出不能选语言/格式；后端 `/files`、`/file/{name}` 无 UI 入口（B6）；无深链到某本书（`offset` 只是内存变量，刷新即丢，`:208`）；3s 全量轮询 summary，页面刷新后浏览位置归零 |
| 读屏用户 | 全部 a11y 缺陷；额外：段落编辑框 placeholder 是原始语言码（`:414`），读屏读出 `chinese_simplified`；进度与费用无 `aria-live` 播报（`PRODUCT.md:130` 明确要求） |

### 3.7 小观察

侧栏百分比永不刷新（轮询里加一次 `loadProjects` 即可）；翻译按钮忽略 `r.ok`；
`partial` 与 `translated` 同为绿色；`main` 高度硬编码与实际头部不符（双滚动条）；
`#content{max-width:960px}` 宽屏留白；日志每 2s 整体重写、概览每 3s 整块重渲染
（滚动位置与选中文字被抹掉）；无 `prefers-reduced-motion`（`PRODUCT.md:132` 要求）；
`select/input` 与 `button` 的 padding/radius 不一致（`:17-19`）；按钮无 focus-visible 与 loading 态；
导出成功只给文件名、无完整路径或"打开输出目录"；`<html lang="zh">` 应为 `zh-CN`。

### 3.8 挑衅性问题

1. 产品承诺"看得见花的钱／随时能停／能续跑"，这三条恰好是界面最缺的三条。
   这个 Web 端到底是给**第一次花真钱的公众用户**用的，还是给开发者看状态的后台？
2. 一个"书"的产品，为什么**没有一处是书页**？把左右对照段落做成真正的双栏排版
   （宋体、行宽 65–75ch、可滚动书页）是否比再调十遍设置表单更接近差异化？
3. "术语分析"是全书级 LLM 调用（花钱），现在和"删除项目"并排躺在"概览"最不显眼处。
   一个花钱动作凭什么是最不需要思考的那个？
4. 19 种语言码自由文本输入，代码里却已有 `LANGS`——这界面是为"配置文件"设计，
   还是为"要读一本书的人"设计？
5. 若 CLI 才是深度用户的归宿，Web 端是否应明确只做三件事（选书 → 选语言 → 看进度），
   把模型/并发/RPM/块预算折进"高级"？

## 4. 交叉核对（两份评估的对照）

| 结论 | Assessment A（人/子代理） | Assessment B（detector） | 综合判定 |
|---|---|---|---|
| 类别可互换 | 判定"像素可互换、schema 已创作" | 未报（查不出） | **A 独有且成立**：detector 没有"设计专属性"这一维度 |
| 费用不可见 | P0-1，并指出 `Stats`/`summary()` 连字段都没有 | 未报 | **A 独有**：这是最严重的问题，detector 结构上查不到 |
| 没有可看的成品 | P0-2 | 未报 | **A 独有** |
| 可访问性 | P1（aria/role/tabindex 全 0、label 无 for、进度条无 role=progressbar） | 只报了标题跳级 | **A 更深**：detector 的规则集不含表单标签与 ARIA 完整性 |
| 标题层级跳级 | 指出 h1→h3→h2 断裂 | `skipped-heading` warning | **两者一致**（唯一重叠项） |
| 字号层级扁平 | 评分表第 8 项扣分 | `flat-type-hierarchy` advisory | **两者一致** |
| 状态机/按钮缺陷 | B2/B3/B5（假成功、按钮永禁用、进度冻结） | 未报 | **A 独有**：这类逻辑缺陷必须在人工评审里抓 |
| 数据丢失 | B1（保存背景吃掉术语编辑） | 未报 | **A 独有**：最严重的一条 |
| GitHub Primer 配色 | 指出具体色值来源 | 未报 | **A 独有**：detector 只判反模式，不判"这是谁的风格" |

**结论**：detector 与人工评审只有 2 项重叠。**把 detector 当作设计门禁是危险的幻觉**——
它能守住"形"，守不住"义"与"逻辑"。因此 `docs/open-source.md` 的 CI 定义里，
detector 是门禁之一而非"设计已达标"的证明；每次发版必须配一次人工评审。

## 5. 综合判断与 v2 对应

### 5.1 总体印象

**骨架是对的**：薄后端 + 单页前端 + 复用同一条 pipeline，让 CLI 与 Web 共享逻辑，
而不是各写一套。**问题是这个骨架里住着一个后台管理界面，而不是一个把书翻好的工具。**

**最大的机会：把"书"放回屏幕中央。** 当前所有交互都围绕"段落"这一抽象单位，
而用户真正关心的是"书"。当书页成为主视图，费用、进度、术语、校对都会自然跟着回来。

### 5.2 优先问题（合并后按严重度）

**P0-1 钱完全不在视野里** —— 一个会按 token 计费的产品，界面上没有一个金额数字，
数据层连字段都没有。修法：`usage.jsonl` 记账 + 开跑前成本闸 + 常驻费用（`docs/ux/web.md` §6、`docs/ux/cli.md` §4）。

**P0-2 没有任何可看的成品** —— 翻译 3000 段时用户看不到一页书。
修法：活页预览（`docs/ux/web.md` §4.1）。

**P0-3 空状态不教人，也不设防** —— 自由文本语言框 + 无成本提示。
修法：四步教学 + 示例书 + doctor 体检（`docs/ux/web.md` §3.1）。

**P0-4 长任务无法停止、无法续跑、结束不通知**（B2/B3/B4/B5 合并）——
这三条承诺恰好是界面最缺的三条。修法：作业条 + `POST /cancel` + 阶段状态机 + 完成事件。

**P1-5 键盘与读屏用户被完全挡在门外**（`aria-*` 0、`role=` 0、`tabindex` 0、label 无 `for=`）。
修法：`docs/ux/web.md` §10。

**P1-6 术语工作流是断的**（按钮在别的页、不能增删行、备注只读、空状态把人赶去改 JSON、
两个保存互相覆盖）。修法：术语页内闭环 + 单一写入口 + dirty 检查（`docs/ux/web.md` §5）。

**P2-7 暗码与英文枚举外泄**（19 语言自由文本而 `LANGS` 是死代码、`fake`/`local`/协议名无解释）。
修法：多选选择器 + 术语化标签（`docs/ux/web.md` §5）。

**方法论备注**：本次评审给开源项目留下一条重要经验——
确定性检测器进 CI 能守住"形"，但**"义"（信息架构、信任、代价可见性）与"逻辑"
（状态机、保存语义、按钮可用性）只能靠人的评审**。
两者缺一，发布出去的就是一个"检测全绿但没人愿意付钱"的工具。
